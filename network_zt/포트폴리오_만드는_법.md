# 포트폴리오 만드는 법

## PART 1 · 전략적으로 포폴 만들기

### 1. 직무별 트렌드 파악하기
- 반드시 채용 공고 사이트(잡코리아, 사람인 등)에서 **수요를 확인**한다.
- 지원할 만한 회사 + 가고 싶은 회사의 **JD(채용 공고의 직무 설명)를 저장** → 분석해서 **교집합**을 구한다.
- 공통 기술 스택 · 요구사항을 정리해서 **포폴 주제**를 만든다.

### 2. 기존에 가지고 있는 도메인 활용하기
취업하고 싶은 분야도 같이 확인한다.
- 전공
- 이전 근무 경험 살리기

### 3. 이미 만든 프로젝트가 있는 수강생
「생각등대」 유튜브를 참고해서 프로젝트를 업그레이드한다.

> **영상 요약** — 6년 차 개발자 「생각등대」가 변화하는 IT 시장에서 살아남기 위해 신입 개발자가 갖춰야 할 핵심 역량을 설명한다.
> - **AI를 활용한 실무 경험 (0:53–2:40)** — 개발자는 단순히 코드를 짜는 사람이 아니라, AI를 적극 활용해 전체 구조를 설계하고 서비스의 정책과 사용자 경험(UX)을 기획하는 역할로 바뀌고 있다.
> - **2027년 개발자 시장의 변화 (2:52–3:38)** — 단순 코딩 업무는 AI가 대체하고, 기술 그 자체보다 서비스의 목적을 이해하고 사용자 문제를 해결하는 기획력과 판단력이 훨씬 중요해진다.
> - **신입 개발자를 위한 조언 (3:52–5:36)** — 기술 공부와 포트폴리오 개수를 늘리기보다, 작은 서비스라도 기획 · 개발 · 운영 · 마케팅까지 전체 과정을 직접 경험하는 것이 훨씬 가치 있는 이력이다. 이제 선택이 아닌 필수다.
>
> **결론** — 앞으로의 개발자는 AI라는 도구로 사용자에게 필요한 가치를 실제로 구현하고 운영하는 「문제 해결사」가 되어야 한다.

### 4. 만든 프로젝트가 없는 수강생
아래 중에서 핵심이 될 만한 것을 **1~3개** 고른다.
- 방어전
- ALEPH 12개 과제
- 취업 에이전트

### 5. 서비스를 제작하는 포폴
- 사용자를 모아서 테스트 → **개선 루프**를 돌린다.
- 인터뷰 · 개선 과정을 **다 기록**해서 포폴로 쌓는다.

### 6. 최종 포폴 형태
**웹사이트 + PDF**

## PART 2 · AI와 단계적으로 만들기

### 포트폴리오 만드는 법 — AI와 단계적으로

바이브 코딩 6주 · 2026-10-21(수)

취업용 포트폴리오 사이트를 AI와 함께 만드는 순서다.
**한 번에 완성하지 않는다.** 재료를 모으고 → 인터뷰로 빈칸을 채우고 → 설계하고 → 만들고 → 계속 고친다.

| 단계 | 하는 일 |
|---|---|
| 0 | 재료 모으기 — 글 기록 전부 + 스크린샷 최소 6장 |
| 1 | 재료 붙여넣기 + 빈칸 인터뷰 |
| 2 | 설계 — 레이아웃 4안 → 색 4안 |
| 3 | 제작 — index.html + images |
| 4 | 개선 — 한 번에 하나씩 |

## 0단계 — 재료 모으기

### ① 글 기록 — 있는 건 전부

- 결정 기록 (막힌 곳 · 고른 방법과 이유 · 배운 것 · 증거)
- 포트폴리오 6가지 항목 초안
- 디자인 브리프
- 처음 정한 주제 한 줄
- AI와 나눈 대화
- 오류 메시지 · 막혔던 메모
- 사이트 소개글 · README

**정리하지 말고 날것 그대로** 붙인다. 정리는 AI가 한다.

### ② 스크린샷 — 최소 6장, 권장 8~10장

이름을 아래처럼 정해 `images` 폴더에 넣는다. 띄어쓰기 없이.

| # | 파일 이름 | 무엇을 찍나 | |
|---|---|---|---|
| 1 | `01-home-pc.png` | 첫 화면 — 컴퓨터 | **필수** |
| 2 | `02-home-mobile.png` | 첫 화면 — 폰 | **필수** |
| 3 | `03-feature-1.png` | 핵심 기능이 돌아가는 화면 1 | **필수** |
| 4 | `04-feature-2.png` | 핵심 기능 2 | **필수** |
| 5 | `05-before.png` | 고치기 **전** 화면 | **필수** |
| 6 | `06-after.png` | 고친 **후** 화면 (5번과 같은 자리) | **필수** |
| 7 | `07-error.png` | 막혔던 순간의 오류 화면 | 있으면 |
| 8 | `08-vercel.png` | Vercel 배포 완료 화면 | 있으면 |
| 9 | `09-feature-3.png` | 핵심 기능 3 | 있으면 |
| 10 | `10-ai-chat.png` | AI가 틀렸던 결정적 대화 장면 | 있으면 |

- 5·6번이 **한 쌍**이어야 한다. "이렇게 바뀌었다"가 포트폴리오에서 제일 설득력 있는 그림이다
- 7번이 있으면 "문제 해결" 화면이 살아난다 — 지금 다시 재현해서 찍어도 된다
- 찍는 법: 맥 `Cmd + Shift + 4` · 윈도우 `Win + Shift + S` · 폰 화면은 실제 폰으로

## 1단계 — 재료 붙여넣기 + 빈칸 인터뷰

사이트를 만들던 채팅창에 붙인다. 그동안의 맥락이 거기 있다.

```
지금부터 내 취업용 포트폴리오 사이트를 만들 거야. 바로 만들지 마.

[1. 재료 받기]
지금부터 내가 가진 기록을 전부 붙여넣을게.
결정 기록, 포트폴리오 초안, 디자인 브리프, AI와 나눈 대화, 오류 메모 같은 것들이야.
길어서 여러 번에 나눠 보낼 거야.
내가 "다 보냈어"라고 할 때까지는 "받았어(○번째)"라고만 답해. 정리하지 마.

[2. 재료 정리 — "다 보냈어" 다음에]
붙인 기록과 이 대화 전체를 읽고, 아래 6가지로 사실만 뽑아서 표로 보여줘.
칸마다 어느 기록에서 나온 내용인지 출처를 같이 적어 줘.
   1. 나는 누구인가 — 전공·학년, 지원하고 싶은 직무, 한 줄 소개
   2. 왜 만들었나 — 누구의 어떤 불편, 계기
   3. 어떻게 만들어 왔나 — 주차별로 한 일, 기간, 쓴 도구, 처음 계획과 달라진 점
   4. 가장 크게 막혔던 순간 2~3개 — 무슨 일 / 어떻게 알아챘나 / 시도한 것(실패 포함) /
      어떻게 넘었나 / 걸린 시간 / 그때 새로 공부한 것
   5. 고른 것과 버린 것 — 뺀 기능, 두 방법 중 고른 순간, 이유,
      AI에게 맡긴 것과 내가 판단한 것
   6. 숫자와 다음 단계 — 셀 수 있는 것 전부(기능 수, 페이지 수, 고친 횟수, 배포 횟수,
      써 본 사람 수, 기간, 뺀 기능 수, 직접 쓴 코드 줄 수), 아쉬운 점, 다음에 할 일
표 아래에 "비어 있는 칸"과 "너무 짧은 칸"을 따로 목록으로 보여줘.

[3. 빈칸 인터뷰]
그다음 비어 있거나 짧은 칸만 나한테 물어봐. 기록에 이미 있는 건 다시 묻지 마.
- 질문은 한 번에 하나만.
- 질문마다 "이렇게 답하면 좋다"는 예시 답을 한 줄 같이 보여줘.
- 내 답이 3줄보다 짧거나 막연하면 넘어가지 말고 더 파고드는 질문을 2개까지 해.
  (예: "그게 몇 주차였어?", "그때 화면에 뭐가 떴어?", "그걸 어떻게 알아챘어?")
- 기록에 흔적이 있으면 네가 먼저 꺼내서 "이런 일이 있었는데 맞아?" 하고 확인받아.
- 내가 말하지 않은 건 절대 지어내지 마. 모르면 비워 둬.

[4. 확인]
인터뷰가 끝나면 6가지 표를 다시 보여주고 "빠지거나 틀린 거 있어?" 하고 물어봐.
내가 확인하기 전에는 다음으로 넘어가지 마.
```

## 2단계 — 설계 (같은 창에 이어서)

```
이제 사이트를 설계하자. 아직 코드는 만들지 마.

[사이트 구조 — 이건 고정]
- 메뉴(상단바 또는 사이드바)로 나뉜 구조. 메뉴를 누르면 그 화면으로 이동.
- 메뉴 구성 제안: 홈 / 프로젝트 / 만든 과정 / 문제 해결 / 배운 것 / 연락
  (내 내용에 맞게 더하거나 빼도 돼. 왜 그렇게 나눴는지 한 줄씩 설명해 줘)
- 모든 화면 맨 위에 숫자 카드 3~4개. 1단계 6번의 숫자만 써. 없는 숫자는 만들지 마.
- 글만 이어지지 않게 화면마다 흐름도(mermaid)·그림(SVG)·스크린샷 중 하나 이상.
  "만든 과정"과 "문제 해결"에는 흐름도를 꼭 넣어.
- 내 스크린샷은 images 폴더에 아래 이름으로 있어. 어느 화면에 어느 사진을 넣을지 정해 줘.
  01-home-pc.png / 02-home-mobile.png / 03-feature-1.png / 04-feature-2.png /
  05-before.png / 06-after.png (그리고 있으면 07~10)

[레이아웃 4안]
서로 완전히 다른 레이아웃 4가지를 미리보기 화면으로 그려서 보여줘.
(예: 상단바형 / 왼쪽 사이드바형 / 큰 첫 화면 + 카드형 / 문서·노트형)
각각 장점 한 줄, 어떤 사람에게 어울리는지 한 줄. 내가 하나 고를게.

[색·스타일 4안 — 내가 레이아웃을 고른 다음에]
고른 레이아웃으로 색 조합·글꼴 느낌이 다른 4가지를 미리보기로 보여줘.
취업용이니까 차분하고 전문적으로. 장난스러운 이모지, 과한 그라데이션, 네온색은 빼.
내가 하나 고를게.
```

## 3단계 — 제작 (고른 뒤에)

```
고른 레이아웃과 색으로 사이트를 만들어 줘.

[파일]
- index.html 하나 + images 폴더. CSS와 JS는 index.html 안에. (Vercel에 그대로 올릴 거야)
- 메뉴를 누르면 그 화면만 보이고 나머지는 숨겨지게.
  주소 뒤에 #projects 처럼 붙어서, 그 주소를 바로 보내도 그 화면이 열리게.
- 폰에서도 안 깨지게. 폰에서는 메뉴가 접히게.

[내용]
- 1단계 표의 사실만 써. 읽기 좋게 다듬되 사실은 바꾸지 마.
- 「혁신적인」「최적화된」「완벽한」 같은 홍보 문구 금지. 겪은 대로만.
- 화면마다: 숫자 카드 3~4개 → 짧은 설명 → 흐름도·그림·스크린샷 → 나머지 글.
- 흐름도는 mermaid, 그림은 SVG를 직접 그려서.
- 05-before.png와 06-after.png는 나란히 놓고 "전 → 후"로 보여줘.
- 아직 없는 사진·링크 자리는 [여기에 07-error.png] 처럼 눈에 띄게 비워 둬.

[다 만들면]
1. 화면별로 무엇을 넣었는지 목록으로.
2. 내가 직접 확인할 것(숫자가 맞는지, 비워 둔 자리, 사진 위치)을 체크리스트로.
3. 이건 첫 판이야. 같이 고쳐 나갈 거야.
```

## 왜 파일 하나인가

| | **index.html 하나 + 화면 전환** (추천) | 페이지마다 파일 따로 |
|---|---|---|
| 겉으로 보기 | 메뉴 누르면 화면이 바뀜 · 주소도 `#projects`로 | 다른 페이지로 이동 |
| AI로 고칠 때 | **한 파일만 고치면 됨** | 메뉴를 고치면 **모든 파일을** 고쳐야 함 — AI가 빼먹어 페이지마다 메뉴가 달라지기 쉽다 |
| 배포 | index.html + images 폴더 | 파일·폴더 구조 신경 써야 함 |

프로젝트가 **3개 이상**으로 늘면 그때 프로젝트별로 파일을 나눈다.

## 4단계 — 만든 뒤 개선하는 법

**원칙: 한 번에 하나만.** "전체적으로 더 예쁘게"는 멀쩡한 곳까지 갈아엎는다.

1. **고치기 전에 백업** — `지금 상태를 backup 폴더에 복사해 둬.` (깃허브면 커밋)
2. **화면 보고 구체적으로 지적**

   | ✗ | ✓ |
   |---|---|
   | 좀 더 깔끔하게 | 프로젝트 화면의 카드 사이 간격을 지금의 두 배로 |
   | 색이 별로야 | 상단바 배경을 한 단계 어둡게, 글자는 흰색으로 |
   | 흐름도가 이상해 | 문제 해결 화면 흐름도 3번째 칸이 화면 밖으로 나가. 세로 방향으로 바꿔 줘 |

3. **레퍼런스 붙여서 비교** — `이 사이트(주소)의 카드 배치를 참고해서 내 홈 화면 숫자 카드만 바꿔 줘. 다른 곳은 건드리지 마.`
4. **숫자 카드 점검** — 카드마다 "이 숫자 어디서 나왔지?"에 바로 답할 수 있어야 한다. 못 하면 지운다. 면접에서 제일 먼저 묻는 게 숫자다.
5. **AI 티 걷어내기** — `사이트 전체에서 홍보 문구, 과장된 표현, 내가 말하지 않은 내용을 찾아 목록으로만 보여줘. 고치지는 마.` → 목록 보고 직접 고른다.
6. **30초 테스트** — 친구한테 주소를 보내고 30초 뒤 "뭐 하는 사람 같아?" 한 줄 소개와 다르면 홈 화면을 고칠 차례.
7. **폰으로 한 번** — 고칠 때마다. 메뉴가 접히는지, 흐름도·사진이 화면 밖으로 안 나가는지.
8. **다시 배포** — Vercel에 연결돼 있으면 저장하면 자동으로 올라간다. 1~2분 뒤 확인.
