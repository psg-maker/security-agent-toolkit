## 오늘 수업내용

네트워크의 네트워크, 인터넷

- 패킷
    네트워크를 통해 데이터를 전송하기 위해 일정한 크기로 나누고, 전달에 필요한 정보를 붙인 데이터 단위

- 라우터(router) - 망과 망을 잇고, 패킷에 적힌 받는 쪽 주소를 보고 다음 장비로 넘김, 회사, 통신사의 큰 장비
- 공유기 - 라우터 기능 + 인터넷 주소 하나를 여러개의 기기에서 나눠 쓰는 것, 집, 작은 사무실이나 학원 등등
- 기본 게이트웨이(default gateway) 다른 망(인터넷)으로 가는 패킷을 받아 넘기는 장비, 보통 공유기

- ping 8.8.8.8(구글의 공개 서버, 인터넷 연결을 확인할 수 있음.)
- 내 pc가 신호를 만듦 -> 기본 게이트웨이, 공유기 - 외부로 넘김 -> 인터넷, 라우터 여러대 -> 8.8.8.8 응답을 만듬 -> 다시 돌아옴

- TTL
- 장비를 지날 때마다 1씩 줄고 0이 되면 패킷이 버려진다.(앞으로 거칠 수 있는 장비의 수)
```
출발 TTL = 3 -> 라우터1 = 2 -> 라우터2 = 1 -> 라우터 3 = 0 => 버림.
```

- ping -n 10 8.8.8.8
- ping에 응답이 없더라도 서버가 꺼졌다고 단정 짓지 않는다

## 4계층 데이터 전송 방식

## TCP(연결 수립을 위한 통신방식)
- 연결 절차를 거치고 보낸다
- 받은 것을 확인, 빠진 것을 다시 보낸다
- 하나도 빠지면 안될 때(log, url, file 등)
## UDP
- 연결 절차 없이 바로 전송한다.
- UDP 자체는 받은 것을 확인하거나 다시 보내지 않는다.
- 조금 빠져도 빨라야할 때(실시간 음성, 영상)

## SYN(synchronize)
- 연결 시작을 요청하는 플래그
## ACK(acknowledge)
- 상대 패킷을 받았다고 알리는 플래그
## FIN(finish)
- 송신 종료
## RST(reset)
- 절차 없이 바로 끊는다.

## 임시 포트
- 연결을 열 때, 운영체제가 자동으로 고르는 자신 쪽의 포트번호(windows 49152~65535)

## TCP의 연결 방식

3-way handshake
- 당일 오전에 본 4계층 전송에는 TCP와 UDP 전송 방식이 존재한다.
- requests.post는 TCP 데이터를 보내기 전에 3-way handshake로 연결을 맺는다.
- 관제에서
연결을 시도만 하고 끝까지 맺지 않는 패킷이 대량으로 오면 공격일수도 있다.
정상 3-way handshake를 알아야 대비할 수 있다.

SYN -> SYN, ACK -> ACK 3-way handshake
