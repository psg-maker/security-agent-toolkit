CONTAINER ID   IMAGE         COMMAND                   CREATED        STATUS                       PORTS                  NAMES

- (가) `docker ps` 의 `PORTS` 열에서 두 서버가 각각 어떻게 나왔는지 적어 주세요.
  - 쓸 내용: ① closed-web-8081 의 PORTS 값 ② open-web-8082 의 PORTS 값
  - 답: closed-web-8081의 PORTS 값은 127.0.0.1:8081->80/tcp이고, open-web-8082는 0.0.0.0:8082->80/tcp입니다. 
  : 전자는 내 PC 안에서만 접속하도록, 
  후자는 모든 네트워크 주소에서 요청을 받도록 설정되어 있습니다.

- (나) 🔍 `내주소` 로 접속했을 때 `closed-web-8081` 과 `open-web-8082` 의 결과(응답 번호)를 각각 적어 주세요.
  - 쓸 내용: ① closed-web-8081 의 응답 번호 ② open-web-8082 의 응답 번호

  open-web-8082는 200이 예상됩니다. 
  000은 HTTP 응답을 받지 못했다는 curl의 표시이고, 200은 요청이 성공했다는 HTTP 응답 코드입니다.

- (다) 🔍 `closed-web-8081` 은 `127.0.0.1` 로 접속하면 열려 있는데 `내주소` 로는 거부되는 이유는 무엇인가요? 다른 PC가 접속하는 경우와 어떻게 같은가요?
  - 쓸 내용: ① 127.0.0.1 로는 열리는 이유 ② 내주소로는 거부되는 이유 ③ 다른 PC가 접속하는 경우와 같은 점
  - 답: closed-web-8081은 -p 127.0.0.1:8081:80으로 설정되어 
  내 PC 자신을 가리키는 루프백 주소인 127.0.0.1로 들어오는 요청만 받습니다.
 따라서 127.0.0.1:8081로는 접속되지만, 내 PC의 실제 네트워크 IP인 내주소:8081로는 접속되지 않습니다. 
 다른 PC도 내 PC의 실제 IP로 접속하므로, 같은 이유로 접속되지 않습니다.

- (라) 🔍 사내 PC에서 접속되면 안 되는 관리용 서버를 켠다면 `-p` 를 어떻게 쓰고, 이것이 4일 차의 어떤 원칙과 같은가요?
